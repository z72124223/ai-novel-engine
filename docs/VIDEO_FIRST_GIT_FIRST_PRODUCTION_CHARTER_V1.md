# AI Novel Engine — 影片優先、Git 優先生產憲章 V1

Status: `ACTIVE_MANDATORY_PRODUCT_CHARTER`

Date: 2026-07-12

## 1. 最終產品定位

本專案的主要終點不是小說，也不是互動遊戲。

主要終點是：

> **可長期連載的影像故事／動畫影片。**

小說文字可以用來測試故事、補充敘事、出版或保存內心描寫，但它是衍生物與審查工具，不是唯一、也不是最高層的最終產品。

正式生產順序固定為：

```text
世界觀與角色資料
→ 故事事件主檔
→ 影視劇本
→ 場景與對白軌
→ 分鏡與鏡頭表
→ 角色／場景固定資產
→ 關鍵影格
→ 單鏡影片
→ 剪輯／聲音／字幕
→ 完整集數影片
```

任何新窗口、GPT、Codex 或協作者都不得因看到小說樣本，就把專案重新定義成「AI 小說生成器」。

## 2. 最高創作權威不是小說全文

真正需要長期固定的資料是：

```text
本場發生什麼
誰在場
每個角色想要什麼
每個角色知道什麼
角色做了什麼選擇
選擇造成什麼後果
正式對白
人物位置與動作
場景時間與光線
使用道具
鏡頭如何銜接
下一場如何延續
```

這些資料形成 `Story Production Master`（故事生產主檔）。

同一份主檔可以衍生：

- 小說版；
- 影視劇本版；
- 漫畫分鏡版；
- 字幕版；
- 圖片交接包；
- 影片鏡頭交接包。

小說文字不得反過來成為唯一權威，迫使所有影片鏡頭照搬長篇旁白。

## 3. 主角方向

陸塵行可以聰明、可靠、敏銳，不需要為了製造衝突而故意犯低級錯誤。

禁止用以下方式推劇情：

- 明知危險仍無理由作死；
- 已證明無效仍不斷重複同一行動；
- 忘記上一場剛得到的資訊；
- 專業能力突然消失；
- 所有人集體降智，只為讓反派成功。

陸塵行的主要成長線放在：

```text
從熟悉地球常識
→ 適應新世界文化、制度與力量規則
→ 理解不同群體如何生存
→ 學會處理權力、人情、政治與責任
→ 從保護自己和愛醬
→ 到承擔更多人的命運
→ 最後能影響戰局與世界
```

他可以一直做出合理判斷；戲劇壓力應來自：

- 資訊不完整；
- 正確選擇也有代價；
- 不同價值無法同時保全；
- 新世界規則與地球經驗不完全相容；
- 對手會學習與改變策略；
- 力量越大，責任與政治後果越大。

## 4. 華語對白與繁體中文母稿

### 4.1 母稿語言

所有正式創作母稿使用：

```text
繁體中文（zh-Hant）
```

陸塵行來自台灣，因此原始口語以自然台灣華語為基礎，但要讓中國大陸、香港、馬來西亞、新加坡與其他華語讀者容易理解。

### 4.2 對話必須像真人

禁止 AI 式對話：

- 每個人都說完整論文；
- 每一句都精準總結價值觀；
- 兩人輪流發表對稱論點；
- 每句都像可截圖的金句；
- 過多「不是 A，而是 B」；
- 每個角色同一語氣；
- 危急時仍講很長、很工整的句子；
- 把角色內心與世界設定全部直接說出來。

自然對話應包含：

- 短句；
- 打斷；
- 停頓；
- 沒回答完整；
- 答非所問；
- 誤解；
- 沉默；
- 看動作就懂、不必說破；
- 不同地區、年齡、職業與關係造成的語氣差異。

### 4.3 角色聲音

至少保持：

- 陸塵行：短句、觀察型吐槽、實作感；
- 愛醬：以行動、反應和選擇表達，不擬人化成說明工具；
- 周克：直接、少話，真正害怕時更沉默；
- 林遙：重證據、追問細節、戒備；
- 對立角色：防衛、利益與自身價值，不用完整演講交代立場。

### 4.4 華人市場發行

生產母稿：

```text
zh-Hant-TW
```

未來發行可由同一主檔衍生：

- `zh-Hans-CN`：中國大陸簡體字幕／文字；
- `zh-Hant-HK`：香港繁體用詞檢查；
- `zh-Hans-MY`：馬來西亞華語可讀性檢查；
- 其他華語地區版本。

不得在同一母稿中任意混用地區詞彙。地區差異需放在 Localization（在地化）資料中管理。

## 5. GitHub 是多人協作的最高工作場所

本專案明確採用：

> **GitHub 遠端 Repository 是多人團隊協作、交接、版本與長期記憶的最高權威。**

本機電腦、Worktree、終端、暫存資料夾、`out/**`、本機 SQLite 與模型工作階段都只是執行環境或快取，不是團隊權威。

### 5.1 任何重要成果都必須進 Git

以下內容不能只留在某一台主機：

- 世界資料變更；
- 劇情事件主檔；
- 小說試稿；
- 影視劇本；
- 對白軌；
- 場景表；
- 分鏡與鏡頭表；
- 評審結果；
- 修訂紀錄；
- 作者決策；
- 圖片／影片交接包；
- Hash；
- 測試報告；
- 開發日誌；
- 啟動與操作說明。

若資料只存在本機 SQLite，必須輸出可讀的 JSON／Markdown／字幕／報告並 Commit 到 Git，才算完成團隊交接。

### 5.2 所有交接使用 Git 身分

任何 GPT／Codex／外部 Agent 的交接都必須包含：

```text
repository
branch
commit SHA
repo-relative path
content SHA-256（需要時）
```

禁止把下列內容當成正式交接：

- `C:\Users\...` 之類私人絕對路徑；
- 「我本機最新版本」；
- 未 Push 的工作樹；
- 只存在終端輸出的結果；
- 沒有 Commit SHA 的「最新版」。

### 5.3 本機環境可以丟掉，Git 不能丟

Codex 應假設：

- 本機 Worktree 可能被刪除；
- 終端可能關閉；
- SQLite 測試資料可能重建；
- 不同 Agent 可能在不同電腦上工作。

只要 GitHub 中的文字、結構化資料、腳本、Hash 與操作說明完整，團隊就能在新主機恢復。

### 5.4 大型媒體檔

正式圖片、音訊或影片若超過一般 Git 大小限制，使用 Git LFS 或經批准的媒體儲存；但 Git 仍必須保存：

- 資產 ID；
- 路徑或受控位置；
- SHA-256；
- 來源 Commit；
- 批准狀態；
- 使用範圍；
- 交接 Manifest。

外部儲存不能取代 Git 的版本索引與批准紀錄。
