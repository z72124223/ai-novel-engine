# Comic Video Workbench CLI Workflow

Status: `IMPLEMENTED_LOCAL_JSON_WORKBENCH_WITH_SETTING_SOURCE_IMAGE_FACING_PROOF_AND_END_TO_END_LOCAL_PREVIEW_BUILD`

This document describes the current local comic video workbench. It is a Kotlin/JVM CLI plus JSON file protocol workflow. It can create an upstream script packet draft from public setting-pack data, produce a local-preview image-facing proof through storyboard validators, then produce metadata packets, validation reports, a render handoff manifest, and an optional local preview MP4 through `build-comic-video-local-preview` or `render-comic-video-local`. The local renderer may generate PNG, WAV, and MP4 files under `out/` or a caller-provided output directory. It does not create provider jobs, sidecar renderer output, registry entries, canon changes, approvals, releases, or production locks.

Current-phase completion report: `docs/COMIC_VIDEO_WORKBENCH_CURRENT_PHASE_COMPLETION.md`.

Next-version prototype for Codex skill/runbook, prompt packets, storyboard production tables, and asset cards: `docs/CODEX_SKILL_SHORT_DRAMA_WORKFLOW_BLUEPRINT.md`.

Implemented first prototype command for that layer: `create-comic-video-production-package-draft`.

Project-local Codex skill/runbook for operating this workflow: `.agents/skills/comic-video-production-package/SKILL.md`.

Committed sample packs: `samples/comic_video_workbench/`, `samples/comic_video_workbench_zh_tw/`, and `samples/comic_video_setting_source/`.

## Boundary

Current allowed output:

- `ScriptPacketDraft` JSON generated from public setting-pack data.
- `SettingPackScriptPacketDraftBuildReport` JSON.
- `SettingImageFacingProofPreviewBuildReport` JSON.
- Local-preview `ImageFacingDeliveryProof` JSON generated through candidate storyboard reports.
- `ComicVideoPacket` JSON.
- `ComicVideoVoiceTimelineFill` JSON supplied by the author/Codex as metadata.
- `ComicVideoPacketValidationReport` JSON.
- `ComicVideoRenderHandoffManifest` JSON.
- `ComicVideoLocalRenderReport` JSON.
- `ComicVideoLocalPreviewBuildReport` JSON.
- `ComicVideoProductionPackageDraft` JSON as a next-version draft-only production package prototype.
- `ComicVideoProductionPackageValidationReport` JSON as the local validation gate for that draft-only production package.
- Local preview media generated by `render-comic-video-local` from a PASS render handoff manifest.

Current forbidden output:

- remote provider URLs or job ids;
- sidecar renderer execution;
- SQLite writes;
- formal asset approval, canon application, registry write, release, or production lock.

## Entry Point

The earliest current setting/world entry point is a public setting pack JSON:

```text
SettingPack JSON
  -> create-setting-script-packet-draft
  -> PASS ScriptPacketDraftValidationReport
  -> build-setting-image-facing-proof-preview
  -> PASS ImageFacingDeliveryProof JSON
```

This setting entry point does not skip the implemented storyboard/image-facing validators. It creates candidate preview artifacts and records which public setting entities were used. Secrets and director-only details are counted as excluded evidence, not copied into visible draft, storyboard, or image-facing fields. It is not a formal accepted-script source binding or human decision.

The existing comic-video entry point still starts after the upstream pipeline has produced a PASS `ImageFacingDeliveryProof` JSON:

```text
accepted script/storyboard pipeline
  -> create-image-facing-delivery-proof
  -> PASS ImageFacingDeliveryProof JSON
  -> comic video workbench workflow
```

The current end-to-end CLI fixture proves this downstream chain:

```text
ImageFacingDeliveryProof JSON
  -> create-comic-video-packet
  -> create-comic-video-voice-timeline-fill-template
  -> fill-comic-video-voice-timeline
  -> validate-comic-video-packet
  -> create-comic-video-render-handoff-manifest
  -> PASS metadata-only render handoff manifest
  -> render-comic-video-local
  -> local preview MP4
```

For normal local preview work, use the wrapper command:

```text
ImageFacingDeliveryProof JSON + edited ComicVideoVoiceTimelineFill JSON
  -> build-comic-video-local-preview
  -> intermediate JSON artifacts
  -> local preview MP4
```

For the shortest setting-source local preview path, use the setting wrapper:

```text
SettingPack JSON + edited ComicVideoVoiceTimelineFill JSON
  -> build-setting-comic-video-local-preview
  -> setting image-facing proof artifacts
  -> comic video local preview artifacts
  -> local preview MP4
```

## Commands

Run commands from the repository root.

### 0. Create a Script Packet Draft from Setting Data

Use this when a public setting pack scene should become structured upstream input for later storyboard and comic-video gates:

```powershell
.\gradlew.bat :app:run --args="create-setting-script-packet-draft --setting-pack samples/comic_video_setting_source/setting_pack_rain_gate_sample.json --scene scene-rain-gate --packet script-packet-draft-rain-gate-sample-001 --build setting-script-packet-rain-gate-sample-001 --out samples/comic_video_setting_source/script_packet_draft_rain_gate_sample.json --validation-out samples/comic_video_setting_source/script_packet_draft_rain_gate_validation.json --report-out samples/comic_video_setting_source/setting_script_packet_draft_build_report.json"
```

Expected result:

- a candidate `ScriptPacketDraft`;
- a `ScriptPacketDraftValidationReport`;
- a `SettingPackScriptPacketDraftBuildReport`;
- `nextAllowedDownstreamStep=script_packet_draft_review` when validation passes.

This command reads setting JSON only. It does not apply a setting pack, write SQLite, create an accepted script packet, create storyboard approval, create image-facing proof, generate media, or touch provider/registry/release/production-lock state.

### 1. Create the Packet

```powershell
.\gradlew.bat :app:run --args="create-comic-video-packet --image-facing-delivery-proof out/comic_video/image_facing_delivery_proof.json --packet comic-video-packet-001 --panel-duration-ms 3000 --out out/comic_video/comic_video_packet.json"
```

Expected result:

- the packet has panel tracks copied from the image-facing proof;
- `voiceCast`, `audioCues`, and `subtitleCues` are still empty;
- `nextAllowedDownstreamStep` remains `comic_video_packet_validation`;
- validation is still required.

- one audio cue and one subtitle cue are created for each panel track;
- cue timings are derived from panel `displayDurationMillis`;
- media/provider/output fields stay blank;
- the output is still an editable metadata template.

### 4. Fill the Voice Timeline


### 5. Validate the Packet

```powershell
.\gradlew.bat :app:run --args="validate-comic-video-packet --comic-video-packet out/comic_video/comic_video_packet_filled.json --validation comic-video-validation-001 --out out/comic_video/comic_video_packet_validation.json"
```

PASS requirements include:

- non-empty panel tracks;
- non-empty voice cast, audio cues, subtitle cues, and timing;
- valid cue references between panels, voices, audio, and subtitles;
- no non-empty generated media output values;
- no non-empty remote/provider values;
- no forbidden final-output, approval, canon, registry, release, or production-lock claims.

On PASS, `nextAllowedDownstreamStep` is `comic_video_packet_validated`.

### 6. Create the Render Handoff Manifest

```powershell
.\gradlew.bat :app:run --args="create-comic-video-render-handoff-manifest --comic-video-packet-validation out/comic_video/comic_video_packet_validation.json --manifest comic-video-render-handoff-001 --out out/comic_video/comic_video_render_handoff_manifest.json"
```

Expected result:

- `verdict` is `PASS`;
- `manifestStatus` is `comic_video_render_handoff_manifest_candidate`;
- panel timeline items use `external_panel_image_required`;
- voice timeline items use `external_audio_required`;
- the manifest remains metadata-only and does not contain media file paths, remote URLs, provider ids, or rendered video paths.

### 7. Render a Local Preview MP4

```powershell
.\gradlew.bat :app:run --args="render-comic-video-local --render-handoff-manifest out/comic_video/comic_video_render_handoff_manifest.json --out-video out/comic_video/comic_video_preview.mp4 --work-dir out/comic_video/local_render_work --report-out out/comic_video/comic_video_local_render_report.json"
```

Expected result:

- `verdict` is `PASS`;
- `renderStatus` is `local_preview_video_rendered`;
- `mediaGenerated` is `true`;
- the output MP4 has local generated panel frames, local Windows speech narration, and burned-in text/subtitle content;
- the JSON report records generated artifacts and local tool evidence;
- no SQLite, provider, remote URL, canon, registry, approval, release, or production-lock state is changed.

Use `--dry-run` to validate the manifest and write a report without creating media:

## Operator Checklist

Before rendering locally or handing the manifest to any future manual renderer or sidecar, confirm:

- the validation report is PASS;
- the manifest was created from the PASS validation report, not from an unvalidated packet;
- every spoken cue has a subtitle cue when subtitles are expected;
- panel ids in voice/subtitle cues match panel ids in the packet;
- no field contains non-empty generated media output, provider job ids, remote URLs, or final render paths;
- JSON packet and manifest files remain metadata-only until `render-comic-video-local` is explicitly run;
- local preview media stays outside source control unless separately approved.
