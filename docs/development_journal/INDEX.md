## Future Append Rule

每次出現下列事情，Codex 應追加 Journal，而不是只留在聊天：

- 使用者改變產品方向；
- 重要美術／劇情／Canon 原則；
- 主角或重要角色的語氣、價值與成長方向；
- 重大技術架構決定；
- 世界來源、SQL、Runtime 之間的真實差異；
- 真實遊玩發現；
- 模型／Provider／成本策略變更；
- 一個舊規則被退休；
- 一個公開專案的設計被正式吸收；
- 重大失敗與教訓；
- 使用者指出專案偏離初衷。

## Integrity Rule

- 不把 Journal 當成目前狀態；目前狀態只由 `PROJECT_STATE.md` 宣告。
- 不刪除使用者批評或失敗紀錄來美化歷史。
- 不寫入 API Key、私人憑證或隱藏系統提示。
- 對無法取得的舊聊天內容要標示缺口，不得假裝逐字完整。
- 可以保存使用者可見對話、Codex 回報、決策摘要與具體 Commit 證據。
- 若一個規劃沒有真正進入 SQL／Runtime／Scenario，Journal 必須明確標記為未落地。
