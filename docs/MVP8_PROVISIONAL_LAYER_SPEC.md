## 0. 一句話

**不必先寫完世界才能讀故事。**  
已鎖定的骨架照演；刻意留白的地方，AI 可補**有靈魂的試用存在**。  
**你和 AI 都能提議升格**——你拍板，AI 也要能自己判斷「這個人值得留下」。

---

## 1. 這層在解什麼問題

| 你的感受 | 試用層怎麼幫 |
| --- | --- |
| 只能當作者，很難當讀者 | 讀者模式：你只說想怎麼做、讀下一段故事 |
| 設定永遠覺得不夠 | 留白區標「這裡故意還沒寫」，授權到點再長 |
| AI 不能創造新角色 | 可在留白區提案臨時人物、生物、傳聞 |
| 怕變成工具人 NPC | 沒有自己慾望、代價、盲點的，一律擋 |
| 累了不想一次定稿 | 試用可先玩；你和 AI 都可往升格清單丟候選 |
| 升格不能只靠作者記得 | AI 劇情推到某點，可自行判斷「此人值得升格」並提出建議 |

---

## 2. 刻意不做的事

- 不接雲端 AI API、不做網頁、不做手機 App。
- 不讓 AI 直接改資料庫（仍由引擎在驗證通過後寫入）。
- 不削弱「作者限定秘密」——角色不能無故知道幕後真相。
- 不把試用層當永久後門，跳過正式設定流程。
- 不因此恢復漫畫 / 影片產線（04–08）。

---

## 3. 世界的四層（由硬到軟）

| 層級 | 白話 | 誰能動 | 讀故事時 |
| --- | --- | --- | --- |
| **鎖定層** | 你已拍板、引擎已載入的正式設定 | 只有正式設定包流程 | 一定會用到 |
| **留白層** | 「這裡還沒寫完」的授權標記 | 你標記；不是虛構內容本身 | AI 知道哪裡可以補 |
| **試用層** | 這一場遊玩裡的臨時人物、傳聞等 | AI 提案 + 引擎驗證通過 | 讀得到、可互動 |
| **定稿層** | 從試用升格後的正式設定 | **你確認**，或**採納 AI 升格建議**後走升格流程 | 變成鎖定層的一部分 |

**衝突時：鎖定層永遠贏。** 試用不能改你已鎖定的內容。

## 4. 塵行的留白區（已定）

這些地方**故意還沒寫完**，AI 可以在劇情需要時補肉：

| 留白區 | 說明 | 可補什麼 |
| --- | --- | --- |
| 第一卷配角網 | 蘇橋、譚霧、薛家、甄嵐等還沒 formal 定稿 | 臨時人物、傳聞 |
| 蒼梧關 | 地理與何時到達還沒鎖 | 小地點補丁、傳聞 |
| 卷一系統細節 | 武器階層、職業、貨幣等還沒精選進正式設定 | 傳聞、勢力跡象 |
| 穿越後線索 | 第一次確認「這裡不是台灣」的證據鏈 | **暫停**；開到穿越段再啟用 |
| 場景局部傳聞 | 讓當下場景感覺「世界還在動」 | 傳聞、路人式臨時人物 |

**禁止試用改動的（鎖定）：**  
陸塵行與愛醬核心人設、台灣開場至廢墟內部主線、逆行門作者限定秘密、修仙基礎規則、五大域宏觀骨架。

清單檔：`world/chenxing/formal/35_provisional_layer_charter_v1.json`

## 5. 試用內容可以是什麼

| 類型 | 例子 |
| --- | --- |
| 臨時人物 | 有主見的路人、可疑的同行者 |
| 生物 | 受驚的動物、異常生物 |
| 勢力跡象 | 遠處號角、不明紋章——不是完整國策 |
| 小地點 | 岔路、破房、地下通道口 |
| 傳聞壓力 | 謠言、未證實的風聲 |

### 能活多久

| 壽命 | 意思 |
| --- | --- |
| 僅本場景 | 預設；離開場景後不再當「既定事實」，可留下傳聞 |
| 本場遊玩可再遇 | 同一場遊玩裡還可能再見到 |
| 升格候選 | 進升格清單；**你或 AI 都可發起** |

## 6. 升格是雙向權利（作者 + AI）

升格不是「只有作者記得去點」。**AI 也要能自己覺得：這個人夠資格留下。**

### 6.1 兩種發起方式

| 誰發起 | 意思 | 結果 |
| --- | --- | --- |
| **你** | 讀完覺得喜歡，手動升格 | 照舊走升格流程 |
| **AI** | 劇情推到某點，提交「升格建議」 | 進清單並標 **AI 建議**；等你確認或駁回 |

**AI 不能偷偷變成正式設定。** 它有的是**建議權與提名權**，不是繞過你的最終拍板。  
但引擎必須認真處理 AI 建議——不能當成可忽略雜訊。

### 6.2 AI 什麼時候可以建議升格

AI 覺得「這個試用存在值得進正式世界」時，可在該回合附上**升格建議**，且必須寫清理由。  
至少滿足下面 **四條裡的三條**（引擎會檢查，湊不滿就擋建議，不准硬提名）：

| 條件 | 白話 |
| --- | --- |
| **有靈魂** | 慾望、代價、盲點、拒絕能力都站得住，不是工具人 |
| **不可替換** | 換成一般路人，這段戲會塌掉或失焦 |
| **讀者會想再見** | 有懸念、關係、威脅或情緒鉤子，不是說完就死 |
| **敘事已落地** | 至少在本場遊玩裡有過互動、衝突或後患，不是只出現一段旁白 |

另外硬性要求：

- 不得與鎖定層衝突  
- 不得把作者限定秘密包進「升格理由」  
- 不得為了升格而升格（沒戲份硬提名 → 擋）

### 6.3 升格建議裡 AI 必須寫什麼

| 欄位 | 要回答什麼 |
| --- | --- |
| 建議升格誰 | 哪一個試用人物 / 存在 |
| 為何夠資格 | 用劇情事實說，不用空話 |
| 讀者價值 | 讀者為何會想再見到他 |
| 不可替換性 | 換掉他會少掉什麼 |
| 若升格 | 建議的正式身份草稿（稱呼、關係、初定位，不是整本設定） |
| 若你不升格 | AI 建議的退場方式（傳聞化、離場、死亡、再遇伏筆等） |

### 6.4 你的權利（不變）

- **你可以升格**，不必等 AI 建議  
- **你可以駁回** AI 的升格建議（理由可選，記一筆即可）  
- **你可以無限期不理**清單——試用照玩，不強迫定稿  

### 6.5 AI 的權利（新增）

- **可以提名升格**——覺得夠資格就寫建議，不必等你先發現  
- **可以反對草率升格**——若某試用存在其實仍是工具人，AI 不應提交建議（引擎也會擋）  
- **可以建議退場**——覺得不值得升格時，在敘事裡自然收掉，並註明「不建議升格」  

### 6.6 清單上的三種狀態

| 狀態 | 意思 |
| --- | --- |
| 試用中 | 還在故事裡跑 |
| **AI 建議升格** | AI 已提名，等你確認或駁回 |
| 作者已升格 / 已駁回 / 已退場 | 結案 |

---

## 7. 「有靈魂」的最低標準

每個試用**人物**提案必須寫清楚：

| 欄位 | 要回答什麼 |
| --- | --- |
| 他想要什麼 | 不是「幫主角推劇情」 |
| 他怕什麼 / 要付什麼代價 | 有成本 |
| 他不知道什麼 | 認知有邊界 |
| 他怎麼說不 | 能拒絕、不配合、退縮 |
| 為何此刻出現 | 為什麼**現在**出場才有趣 |

### 一律擋下的（工具人）

- 只來解釋設定、帶路、送情報  
- 只回答主角問題、沒有自己的打算  
- 說「願意幫忙」「會配合」但沒有代價  
- 知道主角不該知道的幕後真相

## 8. 讀者模式怎麼玩（你一開始要的路線）

```text
你：開一場塵行遊玩（讀者模式）
你：輸入「沿潮間帶往下走」
幕後：AI 寫出本段故事（必要時帶試用提案）
幕後：引擎檢查（秘密、工具人、衝突）
你：讀下一段故事

── 可選，有靈感再做 ──
你或 AI：有人進「升格清單」（AI 會標「我建議升格」）
你：確認 AI 建議 / 自己挑選 → 升格成正式設定包草稿 → 再正式匯入
你：或駁回 AI 建議，讓角色自然退場
```

**讀的時候：** 不用管 JSON、不用管資料庫。  
**仍會擋的：** 洩漏作者秘密、改動已鎖定設定、工具人角色。

讀者試玩第一輪：文風類警告可當**提醒**而非硬擋（硬傷仍擋）。

開場場景：**大坪海岸開場**（`scene-daping-coast-opening`）。

## 9. 升格流程（延後定稿，雙向發起）

```text
試用內容在故事裡活過
  →【你發起】或【AI 提交升格建議】
  → 進升格清單（AI 建議會單獨標記）
  → 你：確認 / 駁回 / 先擱置
  → 若確認：產出「設定包補丁」草稿
  → 你可再改 formal 文件（可選）
  → 驗證 → 預覽影響 → 正式匯入
  → 標記為「已升格」

若你駁回或長期不理：
  → AI 依建議的退場方式收掉試用存在（或維持試用中）
```

升格**不代表自動完美**，只代表「這個靈魂值得寫進正式世界」——**你和 AI 都可以先這樣判斷，但正式寫入仍須你確認。**

## 11. 整體做完怎樣算成功

1. 塵行可用讀者模式開局，至少玩三回合。  
2. AI 可在留白區提案試用人物並寫入「這一場遊玩」。  
3. AI 可在符合條件時提交**升格建議**，清單上可見。  
4. 你可確認或駁回 AI 建議；兩種發起方式都進同一升格流程。  
5. 工具人型提案與草率升格建議被擋。  
6. 已鎖定設定不被試用覆寫。  
7. 升格清單可匯出；正式寫入仍走設定包流程。
